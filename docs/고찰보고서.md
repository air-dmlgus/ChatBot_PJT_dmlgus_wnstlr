# ChatBot 프로젝트 고찰 보고서

## 1. 프로젝트 개요

한끼로그는 사용자가 식단과 영양에 관해 질문하면 생성형 AI가 답변하고, 사용자가 제공한 문서를 검색해 근거로 활용하는 개인 맞춤형 건강 코칭 챗봇이다. 브라우저 화면은 HTML, CSS, JavaScript로 구성했고 FastAPI 서버와 `fetch` 기반 JSON 통신을 사용한다.

## 2. 요구사항 구현 결과

| 요구사항 | 구현 내용 |
|---|---|
| F601 생성형 AI 챗봇 | 일반 AI 모드에서 `POST /chat`을 호출하고 답변을 표시한다. |
| F602 사용자 인터랙션 UI | 대화형 메시지, 입력/전송, Enter 전송, 추천 질문, 로딩·오류 표시를 제공한다. |
| F603 API 요청 및 응답 | `fetch`로 JSON 요청을 보내고 HTTP 오류와 네트워크 예외를 화면에 안내한다. |
| F604 문서 업로드 | PDF·MD·TXT 파일을 `FormData`로 `/upload`에 전송하고 결과 및 문서 목록을 갱신한다. |
| F605 벡터 기반 문서 검색 | 문서 검색 모드에서 `/search` 결과, 유사도, 출처를 표시한다. |
| F606 RAG 응답 | 문서 기반 답변 모드에서 `/integrated-chat`을 호출하고 문서 참고 여부와 출처를 표시한다. |
| F607 고찰 보고서 | 검색 품질, 신뢰성, 한계와 개선 방향을 아래에 정리했다. |

## 3. RAG 동작 흐름

1. 문서를 업로드하면 서버가 파일에서 텍스트를 읽고 일정 길이의 청크로 분리한다.
2. 각 청크를 임베딩 모델로 벡터화하고 ChromaDB에 저장한다.
3. 사용자의 질문도 벡터로 변환해 문서 청크와 유사도를 계산한다.
4. 기준 점수를 넘은 청크를 질문과 함께 생성형 AI에 전달한다.
5. AI 답변과 참고 출처를 사용자 화면에 출력한다.

## 4. 결과 분석 및 한계

문서 검색을 추가하면 모델의 일반 지식만 사용하는 경우보다 특정 가이드나 팀 문서의 내용을 답변에 반영할 수 있다. 문서 검색 모드와 RAG 모드를 분리해 같은 질문에 대해 검색 결과 자체와 생성 답변을 비교할 수 있다. 반면 검색된 청크가 질문과 실제로 관련이 없거나 필요한 문맥이 청크 경계에서 잘리면, 모델이 부정확한 답변을 만들 수 있다. 유사도 점수는 의미상 관련성의 근사치이며 답변의 사실성을 보증하지 않는다. 업로드 문서의 최신성, 표현 방식, 문서의 분량과 품질에도 검색 결과가 영향을 받는다.

또한 현재 시스템은 전문 의료인의 진단이나 영양 처방을 대신하지 않는다. 알레르기, 질환, 복용 약물, 임신 등 개인 상태를 충분히 확인하지 않은 채 구체적인 치료·식단 지침을 제공하면 위험할 수 있다. 따라서 서비스 문구에서 일반 정보와 전문가 상담이 필요한 상황을 구분하고, 건강 관련 질문에 안전한 안내를 제공해야 한다.

## 5. 개선 방향

- 문서별 메타데이터와 최신 수정일을 관리해 오래되거나 중복된 자료를 구분한다.
- 고정 글자 수 청킹 대신 문단·제목 구조를 고려하고, 겹치는 구간을 두어 문맥 손실을 줄인다.
- 여러 검색 결과의 순위를 재평가하는 reranker와 질문 재작성으로 검색 정밀도를 높인다.
- 답변 문장과 인용한 청크를 연결해 사용자가 근거를 직접 확인하도록 한다.
- 대표 질문과 정답 근거를 평가셋으로 만들어 검색 정밀도, 재현율, 답변 근거 일치도를 반복 측정한다.
- 문서 업로드 크기·형식 검증, 사용자 인증, 개인정보 제거와 접근 제어를 추가한다.
- 영양 관련 답변은 출처가 있는 공공기관 자료를 우선하고, 개인 건강정보를 무분별하게 저장하지 않도록 한다.

## 6. 결론

이번 프로젝트를 통해 생성형 AI 서비스는 모델 호출만으로 완성되지 않으며, 사용자 입력부터 API 통신, 문서 전처리, 벡터 검색, 근거 전달, 오류 안내까지 하나의 흐름으로 설계해야 한다는 점을 확인했다. RAG는 특정 문서의 정보를 답변에 연결하는 유용한 방식이지만, 검색 품질과 데이터 품질이 결과를 좌우한다. 따라서 출처 표시와 지속적인 평가를 함께 설계해야 신뢰할 수 있는 서비스에 가까워진다.
